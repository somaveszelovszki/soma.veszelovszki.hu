micro-utils

A collection of portable C++ utility libraries for embedded systems. The libraries don't depend on anything an embedded implementation of the standard library might leave out, and they use static memory allocation only.

View on GitHub
Language
C++17
Build
CMake
Testing
GoogleTest, Google Benchmark
Targets
STM32 + FreeRTOS, desktop

Why it exists

micro-utils is the shared foundation of the babocar firmware. Several microcontrollers needed the same building blocks: containers, control loops, sensor filtering, hardware drivers and a common communication protocol. Rather than copy that code from project to project, it lives in one library that every firmware project links against and that is tested on its own.

Microcontroller firmware can't afford heap fragmentation or surprise allocations, so every container has a fixed capacity known at compile time. The library builds on the Embedded Template Library and uses tiny-json for parsing.

Hardware abstraction

The port layer hides the hardware and the operating system behind one interface. It has implementations for the STM32 HAL and FreeRTOS, plus mock versions of both. The same control and sensor code runs on the car and in unit tests on a laptop, where it can be tested quickly and deterministically.

Libraries

  • container
    STL-like containers with static allocation: vector, map, set, ring buffer
  • control
    Building blocks for control algorithms: PID controller, ramps, maneuvers
  • sensor
    Sensor data filtering and fusion, including a Madgwick AHRS filter
  • hw
    Drivers for DC and servo motors, encoders, IMUs, distance sensors and LCDs
  • port
    Device-independent hardware and operating system abstraction layer
  • panel
    Communication protocols and shared data structures used across units
  • math
    Math helpers: linear algebra, numerics, random number generation
  • debug · log
    Debugging and logging tools for embedded targets
  • format · json
    String formatting and JSON handling without dynamic memory
  • sim
    Simulators, such as a motor model, for testing
  • test
    Unit testing utilities
  • utils
    Low-level utility classes and functions

Testing & performance

Unit tests use GoogleTest and are enabled with BUILD_TESTS. Performance-critical code is measured with Google Benchmark, enabled with BUILD_BENCHMARKS. Both run on the host machine, thanks to the mock port layer.
